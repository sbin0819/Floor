# 예약 2차 통합 실행 결정

14→18은 최신 저장소 지시서를 기준으로 차례로 진행한다. 이 문서는 사용자가 확정한 지시서 보완이다.

- 단계별 검사와 Conventional Commit을 유지한다. 준비 1개, 14의 7개, 15의 9개, 16의 8개, 17의 9개, 추가 전용 시드 1개, 18의 6개로 총 41개를 계획한다.
- 오래된 수정은 참석 취소를 되돌리지 않는다. 수정 입력의 `participantIdsAtLoad`와 잠금 뒤 현재 명단을 비교해 중간에 빠진 사람은 재추가하지 않는다. 새로고침 뒤 명시적으로 다시 초대할 수 있다.
- 기존 참석자는 인증·이메일 자격을 다시 요구하지 않지만 저장할 전체 명단의 외부 참석자 5명 제한은 다시 검사한다.
- 시드 시간 예약에는 17부터 미래 미리 알림을 넣는다. 초대·변경 알림은 넣지 않는다.
- 실제 적용은 전체 검증 뒤 현재 개발용 Neon에 추가형 마이그레이션과 `--booking-round2`만 실행한다. 전체 시드, 비밀번호 초기화, 기존 예약 날짜·지점 설정·소속 변경은 하지 않는다. 기존 `--branches`의 평면도 지점 신규 추가 제한도 유지한다.
- 추가 전용 모드는 지정된 사용 인원 6개, 참석자 5행, 좌석 예약 9개, 점검 1개와 미래 시드 미리 알림만 다룬다. 충돌·누락·부분 적용은 자동 복구하지 않고 중단한다. 재실행은 무변경이며 취소·참석 취소·알림 읽음을 되돌리지 않는다.
- 기존 계정과 `test1@ai.com`부터 `test20@ai.com`, 기존 지점·소속·예약·사진·평면도를 전후 비교한다. 환경 파일은 직접 열거나 수정하지 않고 기존 환경 로더만 사용한다.
- 브라우저는 로그인·조회·선택·이동만 확인한다. 예약·수정·취소·참석 취소·알림 읽음은 실행하지 않는다. Jira·push·배포는 하지 않는다.
- PGlite는 PostgreSQL 다중 연결 교착 검증을 대신하지 않는다. 실제로 확인한 결과와 확인 못 한 것을 구분한다.

## 기준 검사

구현 전 `lint`, `typecheck`, Vitest 151개 파일·2,673개 테스트가 통과했다. Node 22.23.3과 기존 패키지 버전을 유지한다.

## 14 — 사용 인원과 인원 조건

- nullable 사용 인원과 범위 CHECK를 추가했다. 서버는 접근 확인 뒤와 공간 잠금 뒤에 정원을 검사하고, 제목 비공개 예약에는 인원도 전달하지 않는다.
- 공용 입력과 Zustand 초안에 인원·직접 수정 여부를 추가했다. 예약 줄·상세·내 예약·홈에 허용된 인원을 표시한다.
- `people=2–50`은 History API로 바꾸는 클라이언트 조건이다. 목록·시간표를 함께 거르고 선택 공간과 쿼리를 유지한다. 아직 직접 수정하지 않은 양식에만 조건 값을 기본값으로 쓴다.
- 기존 동작 단언은 유지했다. 초안/액션 payload의 새 인원 필드, 양식 펼치기 이름, 홈·달력 인원 배지를 추가했고, `floor-navigation`, `space-detail-streaming`, `select-ssr`의 누락된 새 훅 모의 설정만 보완했다.
- 최초 전체 검사에서는 위 모의 설정 누락 27건이 실패했다. 보완 후 기본·LA 시간대 각각 159개 파일·2,776개 테스트가 통과했다(skip 없음). `lint`, `typecheck`, DB/Auth/OAuth 값을 비운 `build`, `build-storybook`, 기존 Chromium E2E 7개, `db:generate` 무변경도 확인했다.
- Storybook의 기존 지시문/번들 크기 경고와 jsdom의 전체 문서 이동 미지원 안내는 실패가 아니다. 이 단계에서는 실제 Neon에 적용하지 않았다.

## 15 — 오픈 데스크 좌석 예약

- 지점 시간대의 오전·오후·종일, 개인/팀을 합친 한 자리 제한, 구역과 좌석의 점검을 구현했다. 좌석 시간은 시간 예약 한도에서 제외하며 구역 보관 검사에는 자식 좌석 예약을 포함한다.
- 전체 시드에 좌석 예약 9개와 점검 1개를 더했다(빈 DB 전체 예약 30개·점검 5개). 반복 실행·겹침 건너뛰기·선택 지점 보존을 검사했다. 아직 실제 Neon에 적용하지 않았다.
- 좌석 상태·배치를 일괄 조회하고 시간표·목록·기존 단일 시트에 연결했다. 다른 이용자의 신원은 DTO에 없다. 내 예약·홈은 구역 이름/사진/주소와 좌석 이름을 구분한다.
- 기존 엄격한 조회 예산을 유지했다. 층은 `[6,4]`, 시간 예약과 좌석 상세는 `[6,6]`이다. 좌석·예약·점검 JOIN 중복은 UUID별로 합치며 공간 수가 늘어도 SQL 수는 늘지 않는다.
- 변경한 기존 단언: `booking-dal`의 접근 메타데이터 키에 필요한 `bookable`을 추가하고, `floor-member-screen`과 `space-status-line`의 준비 중 문구를 좌석 수로 바꿨다. `desk: null`이 필요한 기존 DTO fixture를 보완했다. 권한·비노출·SQL 예산 단언은 유지했다.
- 지시서의 점검 오류 안내보다 상위 명세를 따라 `SPACE_BLOCKED`에도 배치도를 새로 읽는다. 같은 좌석이라도 제출 뒤 구간을 바꿨으면 늦은 성공이 현재 선택을 지우지 않는다.
- 완료 검사: `lint`, `typecheck`, 기본·LA 시간대 각각 173개 파일·2,910개 테스트(skip 없음), DB/Auth/OAuth 값을 비운 `build`, `build-storybook`, Chromium E2E 7개 통과. `db:generate`는 무변경이다. 첫 전체 검사의 준비 중 문구 단언 1개 실패는 위와 같이 동등하게 갱신한 뒤 재검사했다.

## 16 — 참석자 초대

- 참석자 PK·FK·인덱스와 제약 22, 시드 참석자 5행을 추가했다. 겹침으로 건너뛴 예약의 참석자는 넣지 않으며 시드 재실행·범위 실행·롤백을 검사했다.
- 사람 찾기는 세션 확인 → 사용자별 전체/이메일 검색 제한 → 입력 검증 → 검색 순서다. 같은 팀 부분 검색·외부 전체 이메일 일치, 인증 완료, 본인 제외, 최대 8명, 이메일 가림을 한 SQL에서 처리한다. 외부 이메일 증명은 제출용 초안에만 두고 Query 키·응답·로그에는 넣지 않는다.
- 예약 생성은 정원·자격을 잠금 전후 확인하고 사용자 UUID 순서와 최종 잠금 세기를 지킨다. 참석자 없는 기존 SQL 경로를 유지한다. 참석 취소는 사용자 → 예약 잠금 뒤 조건부 DELETE이며 실패 시 변경이 남지 않는다.
- 내 예약·달력·홈에 초대된 예약을 포함했다. 사진은 SQL JOIN에서 소유자만 읽고, 초대된 예약의 UI에도 사진·공간 이동·취소를 허용하지 않는다. 참석자 이름은 같은 문장에서 집계하며 기존 DAL 인자·문장 수·이번 주 아홉 키를 유지한다.
- 검색 입력·양식·예약 줄은 같은 초안과 입력을 쓴다. 250ms 지연, 이전 요청 취소, 역순 응답, 키보드/포커스, 인원 하한, 늦은 성공과 단일 시트 회귀를 검사했다.
- 기존 화면 테스트 변경: 개인 예약 fixture에 `relation`, `invitedByName`, `participantNames`를 추가하고 빈 초안의 정확한 모양에 `participants: []`를 더했다. `home-new-cards`의 이번 주 링크만 내 예약 달력 주소로 바꿨다. 기존 권한·노출·조회 예산 단언은 그대로 통과했다.
- Node 22.23.3 완료 검사: `lint`, `typecheck`, 기본·LA 각각 185개 파일·3,036개 테스트(skip 없음), DB/Auth/OAuth 값을 비운 `build`, `build-storybook`, Chromium E2E 8개 통과. `db:generate` 무변경. 첫 Storybook 검사의 새 액션 mock 누락을 보완해 재검사했다. 실제 Neon 적용과 브라우저 쓰기 흐름은 아직 실행하지 않았다.

## 17 — 알림과 미리 알림

- 알림 enum·테이블·인덱스와 제약 23, strict 스냅샷 파서를 추가했다. 이메일과 사용자 ID는 스냅샷에 없으며, 미리 알림에는 제목도 없다. 종료 시각을 만료 시각으로 저장한다.
- 생성·취소·참석 취소의 같은 트랜잭션에서 알림을 넣고 지운다. 사용자 행은 UUID 순서로 최종 세기 한 번씩 잠그며, 예약 잠금 뒤 새 참석자를 발견하면 전체 트랜잭션을 최대 3회 다시 시도한다. 본인의 좌석 취소는 기존 잠금/SQL 경로를 유지한다.
- 요약은 `[3]`, 목록은 `[2]`로 읽는다. SQL에서 공개·만료 조건과 예약별 최신 미리 알림을 먼저 거른 뒤 한도를 적용한다. 읽음은 같은 공개 조건의 UPDATE 한 문장이며 타인·미래·만료 알림을 변경하지 않는다.
- 머리글의 종은 계정 메뉴와 독립된 Suspense다. 고정 제목과 버튼 자리를 먼저 보여주고, 종과 페이지는 같은 목록·Query 상태를 쓴다. 모바일 종은 `/notifications`로 간다.
- 기존 액션·권한·정보 노출·조회 예산 테스트는 변경하지 않았다. 새 통합 테스트는 잠금 순서, 제한적 재시도, 이벤트 한 번, 알림 저장 실패의 전체 롤백과 시드 재실행을 검사한다. 실제 PostgreSQL 다중 연결 교착을 재현한 것으로 보고하지 않는다.
- 다른 작업에서 변경된 `.env.example`, 새 `ui4-*` 시안과 `docs/spec/chat.md`는 열람·수정·커밋하지 않고 보존한다.
- 60초·창 복귀·다음 공개 시각 조회, 숨김/10분 유휴 중단, 최초 토스트 제외와 예약별 토스트 교체를 검사했다. 읽음 요청 중 더 늦은 스냅샷이 와도 새 알림을 미리 읽지 않으며 실패는 최신 스냅샷을 보존해 복구한다. 목록이 열린 상태에서 성공하면 서버 목록도 다시 읽는다.
- Node 22.23.3 완료 검사: `lint`, `typecheck`, 기본·LA 각각 201개 파일·3,207개 테스트(skip 없음), DB/Auth/OAuth 값을 비운 `build`, `build-storybook`, Chromium E2E 9개 통과. `db:generate` 무변경. 구현 도중 실행한 첫 빌드는 진행 중인 Query 훅의 타입 오류로 실패했고, 타입을 정리한 뒤 최종 빌드를 다시 통과했다. 실제 Neon 쓰기와 로그인 브라우저 검증은 아직 하지 않았다.

## 추가 전용 시드 — 적용 기록

- `--booking-round2`는 `--branches`, `--reset-passwords`와 함께 사용할 수 없다. 계정을 만들거나 기존 날짜·설정·비밀번호를 바꾸지 않으며, 기존 인증 완료 계정과 부모 관계를 검사한 뒤 추가분만 한 트랜잭션으로 저장한다.
- DB 데이터만으로는 부분 적용과 적용 뒤 참석 취소를 구분할 수 없으므로 로컬 완료 표식을 사용한다. `.floor-local/seed-receipts/`는 Git에서 제외하며 표식에는 버전·호스트 해시·시드 정의 해시·불변 묶음 해시·적용 시각만 둔다. 연결 문자열·비밀번호·토큰·이메일은 저장하지 않는다.
- 표식은 DB 커밋 뒤 원자적으로 생성하고 기존 파일을 덮어쓰지 않는다. 표식이 없는데 추가분이 존재하거나, 표식과 불변 데이터가 다르면 자동 복구 없이 중단한다. 표식 저장 실패도 DB 재실행으로 복구하지 않는다.
- 표식이 있는 재실행은 SELECT만 수행한다. 이후 취소한 좌석 예약, 나간 참석자, 읽은 알림, 수정한 시간 예약을 되돌리지 않는다. 표식은 백업이 아니며 다른 기기에서 재실행하려면 먼저 기존 적용 상태와 표식을 확인해야 한다.
- 전후 검사는 기본 키와 행 해시만 반환한다. 지정된 여섯 예약의 사용 인원 보완 외에는 기존 행의 변경·삭제를 허용하지 않으며, 추가된 행은 별도로 확인한다.
- CLI·표식·전용 시드·전후 검사 4개 파일의 124개 테스트를 직접 실행해 통과했다. 전용 시드는 중간 실패 다섯 지점의 롤백, 좌석/사용자 겹침, 부모·소속 변경, 취소·참석 취소·읽음 뒤 재실행을 검사한다. 기존 전체·범위 시드 회귀를 포함한 별도 155개 테스트도 통과했다. 18의 최종 검증 뒤 실행한 실제 DB 적용 결과는 아래에 기록했다.

## 18 — 예약 바꾸기

- nullable `updated_at`을 추가하는 네 번째 마이그레이션을 생성했다. 기존 예약 전체 값이 보존되고 기존·신규 예약의 수정 시각이 null인 것을 실제 마이그레이션으로 확인했다.
- 본인의 미종료 확정 시간 예약만 수정한다. 시간 변경 때만 시간·한도·점검을 재검사하고, 현재 정원·전체 외부 참석자 수는 항상 검사한다. 사용자 UUID 순으로 최종 세기를 한 번씩 잠그고, 예약 잠금 뒤의 최신 명단으로 조건부 UPDATE·참석자 차이·알림을 같은 트랜잭션에서 처리한다.
- 이전 수정이 참석 취소를 되돌리지 않는다. 위조한 최초 명단도 새 참석자 자격을 대신하지 못한다. 초대·제외·변경 알림은 서로 다른 이전/새 시간 스냅샷을 쓰며, 시간 변경의 미리 알림은 한 번만 다시 만든다. 새 액션 검사 56개와 기존 생성·취소·좌석·참석자·알림 회귀 205개를 통과했다.
- 수정 조회는 `[1,5,5]`의 3단계·11문장이다. 본인·현재 방식의 권한을 확인한 뒤 사진을 읽고 참석자 이메일을 가린다. 자신의 기존 예약을 일정과 하루 합계에서 제외한다. 참가자·공유 팀 수가 늘어도 문장 수는 늘지 않는다.
- 수정 화면은 고정 틀을 먼저 보여주고 각 페이지·조회에서 직접 세션을 확인한다. 기존 입력·타임라인을 재사용하고 초안은 화면 내부에 둔다. 원래 시간이 운영 시간 밖이어도 유지하며, 정원이 1명으로 줄어든 예약의 초과 값을 직접 고칠 수 있다. 충돌 후 입력·최초 명단을 보존하되 최신 참석자의 팀 정보는 반영한다.
- 목록·달력의 본인 미종료 시간 예약에만 바꾸기 링크를 추가했다. 좌석·초대·종료·취소 예약에는 없다. 기존 화면 테스트 단언을 수정하지 않고 새 테스트를 추가했다. 기존 생성·취소 테스트도 그대로 유지했다.
- Node 22.23.3에서 브라우저 확인 전 검사: `lint`, `typecheck`, 기본·LA 각각 **211개 파일·3,419개 테스트**(skip 없음), DB/Auth/OAuth 값을 비운 `build`, `build-storybook`, Chromium E2E **10개** 통과. `db:generate` 무변경. 구현 중 미완성 테스트의 잘못된 Testing Library 옵션으로 첫 빌드 타입 검사가 실패했으나 수정 후 빌드가 통과했다.
- 새 패키지·전역 저장소·서비스는 추가하지 않았다. 관련 코드의 캐시 지시문·건너뛴 테스트·직접 hex 색·렌더 중 현재 시각 취득이 없음을 확인했다. 실제 PostgreSQL 다중 연결 교착 검증은 하지 않았다.

## 개발용 Neon 적용 결과 — 2026-10-08

- 기존 환경 로더로 대상 호스트를 확인했다. 적용 전 DB의 8개 마이그레이션 해시·시각이 저장소와 일치했고, 필요한 인증 완료 계정·기존 예약·부모 관계·새 ID 충돌 검사를 통과했다.
- 추가형 마이그레이션 `0008`–`0011` 네 개를 적용했다. 적용 뒤 총 12개의 마이그레이션 이력이 저장소와 정확히 일치했다.
- 정확한 `SEED_ALLOW_HOST`를 실행 환경에 지정하고 `pnpm db:seed --booking-round2`만 실행했다. 사용 인원 6건 보완, 참석자 5행·좌석 예약 9건·점검 1건·미래 미리 알림 44건을 추가했다. 건너뛴 예약은 없다.
- 적용 전후 23개 앱 테이블을 기본 키와 행 해시로 비교했다. 허용한 여섯 예약의 사용 인원 외에는 기존 행의 변경·삭제가 없었다. 모든 기존 사용자·인증 계정(테스트 계정 20개 포함)·소속·예약 날짜·사진·평면도는 보존됐다. 이 비교는 브라우저 로그인으로 인증 세션이 추가되기 전에 마쳤다.
- 실제 DB 전체는 사용자 29명·지점 5개·층 11개·공간 71개·예약 **34건**·점검 **5건**·참석자 **5행**·공간 사진 65행·평면도 1개·알림 **44건**이다. 빈 PGlite 전체 시드의 예약 30건과 혼동하지 않는다. 기존 시드 시간 예약 중 이미 종료된 9건의 날짜는 옮기지 않았다.
- 완료 표식을 확인한 두 번째 전용 시드 실행은 변경 없이 끝났다. 이번에는 인원 예외도 없는 엄격한 전후 비교로 변경·삭제·추가가 모두 0임을 확인했다. 전체 시드·비밀번호 초기화·계정 생성은 실행하지 않았다.

## 실제 화면과 최종 재검사

- 기존 가상 멤버로 로그인해 데스크톱 1440×900, 태블릿 768×1024, 모바일 390×844를 확인했다. 층의 목록/시간표 전환·인원 조건·좌석 구간·자리 선택·시트 닫기, 내 예약·달력의 초대 및 좌석 표시, 수정 화면과 참석자 검색, 알림 팝오버/페이지, 지점→팀 이동과 뒤로 가기를 확인했다.
- 초대받은 예약은 사진·공간 이동 링크 없이 표시됐다. 수정 화면은 현재 시간·인원·제목을 읽고 검색 결과 이메일을 가렸다. 알림은 아직 공개된 항목이 없는 정상 빈 상태였으며, 미래 44건을 미리 표시하지 않았다. 실제 공개 시각까지 기다리는 폴링·토스트 검사는 하지 않았고 타이머 회귀는 자동 검사로 확인했다.
- 모바일 좌석 배치도 높이가 20px까지 눌리는 문제를 발견해 `DeskPicker`의 과도한 축소를 막고 배치도 최소 영역을 확보했다. 수정 뒤 실제 좌석 영역은 208px, 버튼은 44px이었으며 24개 좌석과 하단 양식까지 내부 스크롤로 접근했다. 예약된 자리에도 키보드 포커스가 도달하고 화살표·Enter로 빈 자리를 선택했다. 데스크톱은 420px 오른쪽 시트, 좁은 화면은 아래 시트이며 열린 dialog는 하나였다.
- 위 보완 후 `lint`, `typecheck`, 기본·LA 각각 **211개 파일·3,420개 테스트**, DB/Auth/OAuth 값을 비운 `build`, `build-storybook`, Chromium E2E **10개**를 다시 통과했다. `db:generate`는 무변경, 조회 계측 27개 재검사도 통과했다. 브라우저 콘솔의 오류·경고와 Suspense 경고는 확인한 흐름에서 없었다.
- 실제 브라우저 예약·수정 저장·취소·참석 취소·알림 읽음은 **확인 못 함**이다. 일부러 응답을 지연시킨 시트 입장 애니메이션 횟수와 역순 응답의 모든 조합도 이번 브라우저에서는 다시 측정하지 않았다. 관련 자동 회귀는 유지했다. PostgreSQL 다중 연결 경합·교착 검증은 **확인 못 함**이다.
- 로컬 완료 표식은 보관한다. 사람이 다음으로 확인할 흐름은 두 계정으로 시간 예약·참석자 초대 → 좌석 예약 → 미리 알림 → 참석 취소와 예약 수정 → 취소다. 다른 환경에서는 마이그레이션을 별도로 적용해야 한다. 인메모리 검색 제한은 인스턴스 간에 공유되지 않으므로 배포 전에 공용 제한기를 검토하고 검색 URL의 이메일을 프록시·관측 로그에서 가려야 한다.
- 계획한 41개 커밋 중 마지막 검증 커밋에 위 모바일 보완과 기록을 함께 포함한다. 작업 도중 생긴 사용자 소유 `.env.example`, `docs/spec/chat.md`, `docs/design/ui4-*`는 그대로 남기고 커밋하지 않는다. 따라서 전체 작업 트리가 깨끗하다고 보고하지 않는다. 환경 파일 직접 열람·수정, Jira 접속, push·배포는 하지 않았다.
