# 작업 지시서 10 — 공간 사진과 전체 인상

지시서 09까지 끝난 뒤에 한다. `docs/spec/ui.md`의 스켈레톤·낙관적 이동 도구와 단계를 재는 테스트 도구(`tests/db`)가 없으면 시작하지 말고 알린다.

## 목표

끝났을 때 아래가 모두 참이어야 한다.

- 디자인 토큰이 `docs/spec/design-tokens.md`의 "(2차)" 값이다: 굵기 700, 모서리 10px과 14px, 카드의 그림자, `booked` 토큰.
- 머리글, 페이지 머리, 카드, 구획 선택, 상태 한 줄이 `docs/spec/ui-2.md`의 "전체 인상"대로다.
- 공간 사진과 지점 대표 사진이 DB에 있고(`space_photos`, `branches.cover_photo_*`), `pnpm db:seed`가 `docs/spec/examples/seed-photos.json`을 넣는다.
- 조회가 사진을 싣는다. 접근할 수 없는 공간의 사진은 싣지 않는다.
- 사진 컴포넌트(작은 사진, 자리 표시, 넘겨 보기, 크게 보기)가 있고, 지금 화면의 공간 줄·공간 상세·홈·지점 카드에 사진이 보인다.

화면의 구성(시간표, 달력, 홈의 새 카드)은 이 작업에서 바꾸지 않는다. 지시서 11과 12에서 한다. 이 작업은 그 바탕이다.

- 구획 선택 컴포넌트를 만든다: 링크 묶음(`nav` 안의 `<a>`, 지금 것에 `aria-current`)이고, 옅은 회색 바탕 위에 고른 것만 흰 바탕과 `shadow-card`. 07의 낙관적 선택 도구와 같이 쓸 수 있어야 한다. 층 탭과 내 예약의 탭을 이 컴포넌트로 바꾼다 (동작은 그대로).

### 4. 사진 시드

`docs/spec/examples/seed-photos.json`을 넣는다. 파일의 모양은 파일 안의 `note`와 `docs/spec/ui-2.md`의 "사진 › 데이터"에 있다.

- `seed.json`의 스키마는 건드리지 않는다. `seed-photos.json`을 읽는 스키마를 따로 둔다 (`z.strictObject`, 경로와 대체 글은 3단계의 스키마). `width`, `height`, 항목의 `name`은 사람이 읽으라고 넣은 값이다. 받되 DB에 넣지 않는다.
- 검증: `spaceId`와 `branchId`가 시드의 공간과 지점에 있다. 좌석(`type = 'desk'`)에는 사진이 없다. 한 공간의 사진이 10장을 넘지 않는다. 같은 공간에 같은 경로가 두 번 나오지 않는다.
- `pnpm db:seed`가 지금의 시드와 같은 트랜잭션에서, 지금과 같은 방식(다시 돌려도 같은 결과)으로 넣는다. 파일에서 빠진 사진은 그 공간에서 지운다 (시드에 있는 공간의 사진만 건드린다). 지점의 대표 사진도 같다.
- 시드의 안전장치(`SEED_ALLOW_HOST`, 배포 환경 거부)는 그대로다.
- 테스트
  - `seed-photos.json`이 스키마를 통과한다.
  - 파일이 가리키는 경로마다 `public/` 아래에 실제 파일이 있다. `public/seed/photos/`에 있는데 아무도 가리키지 않는 파일이 없다.
  - 시드를 두 번 돌려도 `space_photos`의 행 수가 41이고, 공간마다 `sort_order`가 0부터 빈틈없이 이어진다.
  - 리뷰룸과 폰부스 S-1에는 사진이 없다.

### 5. 조회에 사진 싣기

`docs/spec/ui-2.md`의 "조회에 더하는 것" 표에서, 지금 있는 조회에 해당하는 줄을 따른다.

- `getFloorDay`: 접근 가능한 공간마다 `photo: { path, alt } | null`.
- `getSpaceDay`: `photos: { path, alt }[]` (순서대로, 없으면 빈 배열). 이 조회는 이미 한 단계의 문장이 6개다. 문장을 더하지 않는다: 사진을 공간을 읽는 문장에 합치거나, 다른 문장을 JOIN으로 줄여 자리를 만든다.
- 홈의 지금 비어 있는 공간, 홈의 다가오는 예약, `getMyBookings`: 공간의 대표 사진.
- 지점 목록과 층 화면의 지점 줄: 지점의 대표 사진 `cover: { path, alt } | null`. 지점 목록에는 "내가 접근할 수 있고 예약할 수 있는 공간의 수"도 더한다 (12가 쓴다).
- 공간 목록과 홈의 빈 공간의 사진은 접근할 수 있다고 판정한 공간의 id로만, 둘째 단계에서 읽는다. 전부 읽어 온 뒤 코드에서 거르지 않는다. 내 예약의 사진은 그 예약의 공간 것을 읽는다 (명세의 예외). 단계 예산과 "한 단계 문장 6개"를 지킨다. 넘으면 JOIN으로 합친다.
- 예산 테스트를 고친 조회마다 다시 통과시킨다.
- 노출 테스트를 더한다: 김하은(팀 없음)의 `getFloorDay`(7층), 홈의 조회들, 지점 목록 결과를 JSON으로 바꿨을 때 `meeting-large-clay`(회의실 A만 쓰는 사진), `meeting-large-sand`(디자인 스튜디오만), `phone-booth-sage`(폰부스 8-1만)가 없다. 다른 사진 파일은 여러 공간이 같이 쓰므로 이 세 이름으로 확인한다. 7층에서 회의실 A를 쓸 수 있는 팀의 팀원에게는 `meeting-large-clay`가 있다. 전용 공간의 항목은 여전히 `{ kind, id, type }`뿐이다 (키가 셋이다).

### 6. 사진 컴포넌트

`docs/spec/ui-2.md`의 "보여주는 방식"과 "사진 넘겨 보기"를 따른다.

- 작은 사진: `{ photo, type, size }`를 받아 사진이나 종류별 자리 표시를 같은 크기로 그린다. 전용 공간용 자리 표시(빗금과 자물쇠)도 있다. 옆에 이름이 있는 줄에서 쓰도록 `alt=""`로 그리는 선택지가 있다.
- 사진 넘겨 보기: CSS scroll-snap. 사진 수가 0, 1, 2 이상일 때의 모습이 각각 맞다. 버튼, 점, "1 / 3", 화살표 키, 끝에서 버튼 비활성, 이름과 역할은 명세대로. 보이는 사진의 번호는 스크롤 위치에서 구한다 (`IntersectionObserver`나 스크롤 이벤트). `prefers-reduced-motion`이면 `scroll-behavior`를 부드럽게 하지 않는다.
- 크게 보기: 사진은 버튼이다 (이름 "사진 크게 보기"). 누르면 `dialog`로 같은 넘겨 보기를 크게. 대화상자 안의 사진은 버튼이 아니다. 제목은 공간 이름. 닫으면 포커스가 누른 사진으로 돌아온다. 점은 장식이다 (`aria-hidden`).
- 첫 장만 먼저 읽고 나머지는 늦게 읽는다. 먼저 읽게 하는 방법은 설치된 문서가 권하는 것을 쓴다 (`priority`는 설치된 버전에서 쓰지 말라고 돼 있다). `sizes`를 쓰이는 크기에 맞춘다.
- 사진의 스켈레톤: 같은 크기의 회색 틀.
- Storybook: 작은 사진(사진 있음, 없음, 전용), 넘겨 보기(0장, 1장, 3장).
- 컴포넌트 테스트: 3장일 때 "다음 사진"을 누르면 "2 / 3"이 되고 "이전 사진"이 활성이 된다. 마지막 장에서 "다음 사진"이 비활성이다. 1장이면 버튼과 점이 없다. 0장이면 자리 표시가 보인다. 역할과 이름이 명세대로다. jsdom에서 스크롤이 일어나지 않아 번호를 확인할 수 없으면, 번호를 정하는 부분을 순수 함수로 떼어 그것을 테스트하고 보고에 적는다.

### 7. 지금 화면에 사진 붙이기

구성은 그대로 두고 사진만 붙인다. 11과 12가 구성을 바꿀 때 다시 손댄다.

- 층 화면의 공간 줄: 이름 왼쪽에 작은 사진. 전용 공간 줄은 빗금과 자물쇠의 자리 표시.
- 공간 상세(패널과 시트): 맨 위에 사진 넘겨 보기. 닫기 버튼(이름은 지금 그대로 "공간 상세 닫기")은 사진 위 오른쪽에 겹친다. 이 단계에서는 사진의 높이를 120px로 둔다 (11에서 패널을 다시 짜면서 160px로 한다. 지금은 하루 일정의 자리를 더 줄이지 않는 것이 먼저다).
- 홈의 지금 비어 있는 공간의 줄, 다가오는 내 예약의 줄: 작은 사진.
- 내 예약의 줄: 작은 사진.
- 지점 카드: 위에 대표 사진. 층 화면의 지점 버튼: 작은 사진.
- 스켈레톤을 사진 자리만큼 맞춘다.
- 사진이 붙어 구조가 바뀌는 바람에 깨지는 화면 테스트는, 확인하는 내용을 그대로 둔 채 새 구조에 맞게 고친다. 고친 테스트를 보고에 적는다. 액션, 노출, 예산 테스트는 고치지 않는다.

### 8. 문서와 마무리

- `README.md`에 사진(어디에 있고 어떻게 시드로 들어가는지, 실제 사진으로 바꾸려면 무엇을 고치는지)과 새 컴포넌트를 짧게 적는다.
- `AGENTS.md`에는 이미 규칙이 적혀 있다. 실제로 만든 것과 다르면 고친다.

## 막혔을 때

- 설치된 Next.js에서 로컬 경로의 사진에 설정이 필요하면 그 설정을 가장 좁게 넣는다 (`/seed/photos/` 아래만). 바깥 주소를 허용하는 설정은 넣지 않는다.
- 사진을 싣느라 어떤 조회가 예산을 넘으면, 접근 확인을 빼지 말고 어느 조회가 왜 넘는지 알린다.
- 시안과 명세가 다르면 명세가 맞다. 명세에 없는 것은 시안을 따른다. 둘 다 없으면 더 단순한 쪽으로 정하고 보고에 적는다.
- 문서끼리 다르면 `AGENTS.md`, `docs/spec/ui-2.md`, `docs/spec/ui.md`, 그 밖의 `docs/spec/`, 이 지시서 순으로 우선한다.
