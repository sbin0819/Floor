# 화면 구성과 로딩

지시서 01–06으로 기능은 끝까지 돌아간다. 이 문서는 그 위에서 화면의 구성, 로딩 상태, 응답 속도를 정한다. 기능 규칙(누가 무엇을 할 수 있나, 결과 코드, 한도)은 바꾸지 않는다. 그 규칙은 `docs/spec/auth.md`, `docs/spec/booking.md`, `docs/spec/space-admin.md`에 있다.

시안은 `docs/design/ui-*.png`다. 색, 글자 크기, 간격은 `docs/spec/design-tokens.md`를 따르고, 시안은 배치와 정보의 순서를 보여 준다. 시안의 글꼴과 가상 데이터는 따라 하지 않는다.

## 지금 무엇이 문제인가

2026-10-07에 개발 서버에서 잰 값이다 (DB는 Neon `us-east-2`, 접속은 한국).

| 화면 | 서버 응답이 끝나기까지 | 그동안 보이는 것 |
| --- | --- | --- |
| 홈 | 2.3초 | "홈을 불러오고 있어요." 한 줄 |
| 층 화면 | 3.1초 | "공간을 불러오고 있어요." 한 줄 |
| 층 화면에서 공간을 고름 | 6.5초 | 아무 변화 없음. 이전 화면이 그대로 멈춰 있다 |
| 날짜를 바꿈 | 약 3초 | 아무 변화 없음 |

원인은 셋이다.

1. 한 요청 안에서 DB를 15–30번 차례로 부른다. 세션 확인을 머리글, 페이지, 조회 함수가 각자 다시 하고, 조회도 하나가 끝나야 다음을 시작한다. 공간 상세는 층 조회가 끝난 뒤에야 시작한다.
2. 로딩 상태가 화면 전체를 글자 한 줄로 바꾼다. 바뀌지 않는 부분(머리글 아래의 지점, 층 탭)까지 사라진다.
3. 주소의 쿼리만 바뀌는 이동(날짜, 공간 선택)은 눌렀다는 표시가 전혀 없다.

## 조회 속도

화면을 다듬기 전에 서버가 덜 기다리게 한다.

- 한 요청 안에서 같은 조회를 두 번 하지 않는다. 세션, 내 소속(권한 컨텍스트), 지점, 층은 React의 `cache()`로 요청 단위로 한 번만 읽는다. `cache()`는 한 번의 서버 렌더 안에서만 값을 나누고 요청이 끝나면 버려지므로, "세션과 권한을 요청 사이에 캐시하지 않는다"는 규칙에 어긋나지 않는다. `use cache`는 여전히 쓰지 않는다.
  - `cache()`로 감싸는 함수의 인자는 문자열 같은 원시 값이어야 한다 (`(userId, branchId)`). 객체를 넘기면 호출마다 다른 인자로 보아 메모가 되지 않는다.
  - 세션은 `getSession()`만 감싼다. `requireSession()`, `requirePageSession()`, `requireOperatorPage()`는 감싸지 않고 그 위에서 동작한다 (이 함수들은 이동을 일으키고 인자가 호출마다 다르다).
  - `cache()`는 실패도 기억한다. 한 요청 안에서 같은 인자로 다시 불러도 같은 오류가 난다. 다시 시도는 새 요청에서 한다.
- 서로 기다릴 필요가 없는 조회는 `Promise.all`로 같이 보낸다. 주소에 있는 id(지점, 층, 공간)로 읽을 수 있는 것은 한꺼번에 읽고, 읽은 뒤에 서로 맞는지(층이 그 지점의 층인지 등)와 접근 권한을 확인한다. 확인 순서가 아니라 확인 결과가 같으면 된다. 확인에 실패하면 지금과 같은 코드를 돌려준다.
- 화면의 독립된 영역은 각자의 `<Suspense>`에서 따로 읽는다. 한 영역이 다른 영역을 기다리지 않는다. 층 화면의 공간 상세는 공간 목록과 동시에 읽기 시작한다. 공간 상세 조회는 주소의 `branchId`, `floorId`를 같이 받아 첫 단계에서 한꺼번에 읽고, 공간이 정말 그 층과 그 지점의 것인지는 읽은 행으로 확인한다 (주소를 믿지 않는다).

조회마다 "단계"의 예산을 둔다. 단계는 앞 단계의 결과를 받은 뒤에 보내는 SQL 문장의 묶음이다. 같이 보낸 문장들은 한 단계이고, 여러 테이블을 JOIN으로 묶은 한 문장도 한 단계다. 세션 확인은 예산에서 뺀다.

| 조회 | 세션 확인 뒤 단계 수 |
| --- | --- |
| 홈의 머리, 다가오는 내 예약, 내 팀 | 2 이하 |
| 홈의 "지금 비어 있는 공간", "오늘 예약 한도", `/booking`이 갈 곳 | 3 이하 (어느 지점인지 → 그 지점의 층·공간·내 권한 → 예약) |
| 지점 목록 | 2 이하 |
| 층 화면의 지점 줄(층 목록), 공간 목록, 공간 상세 | 각각 2 이하 |
| 내 예약, 팀, 팀 화면, 팀 전환 | 2 이하 |
| 운영자 화면의 각 조회 | 2 이하 |

- 한 단계에 같이 보내는 문장은 6개까지다. 문장마다 DB 연결을 하나씩 쓰기 때문이다. 더 필요하면 JOIN으로 문장을 합친다.
- 예산은 테스트로 확인한다. 걸린 시간이 아니라 순서로 잰다. 테스트용 DB 래퍼가 들어온 문장을 바로 실행하지 않고 모아 둔다. 더 들어오는 문장이 없으면(타이머 한 번을 양보한 뒤) 모인 문장을 한 묶음으로 실행하고, 결과를 모두 받은 뒤에 한꺼번에 돌려준다. 이 묶음 하나가 한 단계다. 조회 함수의 단계 수는 묶음의 수이고, 같은 래퍼로 문장 수도 센다. 기다리는 시간에 기대지 않으므로 느린 CI에서도 결과가 같다.
- 조회 수를 줄이려고 권한 확인을 빼지 않는다. 접근을 판정하는 첫 단계에서 공간은 id, 종류, 이용 대상만 읽는다. 이름, 정원, 편의 시설과 예약·점검은 접근할 수 있다고 판정한 공간의 id로 다음 단계에서 읽는다. 접근할 수 없는 공간의 이름과 일정을 읽어 온 뒤 코드나 화면에서 가리는 방식을 쓰지 않는다. 수만 세는 조회는 제목과 예약자 이름 컬럼을 읽지 않는다.
- 클라이언트 컴포넌트에 넘기는 값은 그 화면에 쓸 필드만 담은 객체다. DB에서 읽은 행을 그대로 넘기지 않는다.
- 지점이 여럿이어도 조회 수가 지점 수에 비례해 늘지 않게 한다 (지점마다 조회를 반복하지 않는다).

## 로딩 상태

### 스켈레톤

- 모든 `<Suspense>`의 fallback은 그 자리에 올 내용과 같은 틀의 스켈레톤이다. 글자 한 줄짜리 fallback을 남기지 않는다.
- 스켈레톤은 실제 내용과 같은 격자, 같은 높이를 쓴다. 내용이 들어올 때 화면이 밀리지 않아야 한다.
- 스켈레톤의 맨 바깥 요소에 `aria-busy="true"`와, 화면에 보이지 않는 상태 문구("불러오고 있어요")를 담은 `role="status"` 하나를 둔다. 스켈레톤이 내용으로 바뀌면 둘 다 같이 사라진다. 내용 쪽에 `aria-busy`가 남으면 안 된다. 스켈레톤 조각 하나하나에는 이름을 붙이지 않고 `aria-hidden`으로 둔다.
- 움직임(반짝임)은 `prefers-reduced-motion`이면 끈다.
- shadcn의 `skeleton`을 더해 쓰고, 화면별 스켈레톤은 그 화면의 컴포넌트 옆에 둔다.

### 바뀌는 부분만 바꾼다

| 사용자가 누른 것 | 누른 즉시 | 스켈레톤이 되는 곳 | 그대로 남는 곳 |
| --- | --- | --- | --- |
| 머리글의 메뉴 | 누른 메뉴가 선택 표시 | 머리글 아래 전체 | 머리글 |
| 지점 목록의 지점 | 누른 카드가 눌림 표시 | 머리글 아래 전체 | 머리글 |
| 층 탭 | 누른 탭이 선택 표시 | 공간 목록. 공간 상세는 바로 "공간을 골라 주세요" 상자 (층을 바꾸면 공간 선택이 빠진다) | 머리글, 지점 줄, 층 탭, 날짜 줄 |
| 날짜 | 누른 날짜가 선택 표시 | 공간 목록. 공간이 골라져 있으면 공간 상세도 | 머리글, 지점 줄, 층 탭, 날짜 줄 |
| 공간 목록의 공간 | 누른 줄이 선택 표시 | 공간 상세 | 그 밖의 전부. 공간 목록도 그대로다 |
| 공간 상세의 닫기 | 상세가 바로 닫힘 | 없음 | 그 밖의 전부 |
| 내 예약의 탭 | 누른 탭이 선택 표시 | 예약 목록 | 머리글, 제목, 탭 |
| 팀 전환의 고르기, 다시 고르기 (`mode`가 바뀜) | 다음 단계의 제목과 틀이 바로 보임 | 양식 안에서 조회가 필요한 부분만 | 머리글 |
| 운영자 화면의 지점, 층 | 누른 항목이 선택 표시 | 내용 영역 (경로 표시 포함) | 왼쪽 메뉴 |

- "누른 즉시"는 서버 응답을 기다리지 않는다는 뜻이다. 주소의 쿼리만 바뀌는 이동은 React가 이전 화면을 그대로 두므로, 클라이언트에서 낙관적 값으로 선택 표시와 스켈레톤을 먼저 보여준다. 방법은 설치된 Next.js 문서의 `01-app/02-guides/interactive-apps.md`("Filter with pending feedback")를 따른다: 이동을 `startTransition` 안에서 하고, `useOptimistic`으로 고른 값을 먼저 반영한다. 링크 하나의 대기 표시만 필요하면 `useLinkStatus`를 쓴다.
- 기준 값은 지금 주소를 서버와 같은 규칙으로 정리한 값이다. 층은 `useParams`의 `floorId`, 날짜는 `useSearchParams`의 `date`를 서버와 같은 순수 함수에 넣은 결과(없거나 틀리거나 범위 밖이면 레이아웃이 내려준 오늘)다. 공간은 공간 상세 영역의 서버 컴포넌트가 내려주는 "실제로 그려진 공간의 id"(없으면 null)다. 주소의 `space`를 그대로 믿지 않는다.
- 낙관적 값은 이동이 진행 중일 때만 기준 값과 다르다. 스켈레톤은 "이동이 진행 중이고, 낙관적 값이 기준 값과 다른" 동안에만 보인다. 이동이 끝나면 낙관적 값은 기준 값으로 돌아가고 서버가 그린 내용이 보인다. 새로 고침이나 주소로 바로 들어온 화면에서는 낙관적 상태가 없고, 선택 표시와 시트의 열림은 기준 값에서 나온다.
- 주소의 `space`가 그 층의 공간이 아니거나 내가 쓸 수 없는 공간이면 지금처럼 고르지 않은 것으로 본다 (`docs/spec/booking.md`). 공간 상세 조회가 `NOT_FOUND`를 내면 공간 상세 영역은 `notFound()`를 부르지 않고 "공간을 골라 주세요" 상자를 그린다. 선택 표시가 없고 시트도 열리지 않는다. 층에 접근할 수 없는 경우의 `notFound()`는 공간 목록 영역이 맡는다.
- 이동한 뒤에도 공간이 골라져 있을 때만 공간 상세가 스켈레톤이 된다. 층을 바꾸거나 닫을 때처럼 공간 선택이 빠지는 이동에서는 바로 "공간을 골라 주세요" 상자를 보여준다.
- 낙관적 값은 선택 표시와 스켈레톤에만 쓴다. 서버가 돌려준 데이터를 낙관적으로 바꾸지 않는다.
- 서버가 다른 값을 돌려주면(없는 공간, 범위 밖 날짜) 서버 값으로 돌아간다.
- 층 탭, 날짜, 공간 줄, 내 예약의 탭은 링크다. 여기서 "탭"은 링크의 목록(`nav` 안의 `<a>`, 지금 것에 `aria-current`)이고 shadcn의 `tabs`가 아니다. `next/link`의 `<Link href>`에 `onClick`을 달아 가로챈다. 새 탭으로 열기와 주소 공유가 그대로 된다.
  - 보조 키(Ctrl, Cmd, Shift, Alt)를 누른 채거나 왼쪽 버튼이 아니면 가로채지 않는다.
  - 가로챌 때는 `await` 없이 바로 낙관적 값을 바꾸고 이동한다. 그 앞에 기다리는 일을 두지 않는다.
  - 층, 날짜, 공간, 탭을 고르는 이동은 `router.push`, 공간 상세를 닫는 이동은 `router.replace`다.
- 지점 줄, 층 탭, 날짜 줄은 층이나 날짜가 바뀌어도 다시 만들어지지 않게 `/branches/[branchId]/layout.tsx`에 둔다.
  - 레이아웃은 지점, 내가 접근할 수 있는 층 목록, 요일별 운영 시간, 지점 시간대의 오늘과 지금을 읽어 내려준다. 레이아웃은 `searchParams`를 받지 못하므로, 층 탭의 선택 표시, 날짜 줄, 그 날짜의 운영 시간 표시, 낙관적 값을 나누는 컨텍스트는 `useParams`와 `useSearchParams`를 쓰는 클라이언트 컴포넌트다. 각각 `<Suspense>` 안에 둔다 (Cache Components에서 빌드 오류를 피한다).
  - 레이아웃은 접근을 막는 수단이 아니라는 규칙은 그대로다. 레이아웃 안의 조회는 `getSession()`으로 세션을 본다. 세션이 없으면 스켈레톤만 그린다 (로그인 화면으로 보내는 것은 `next`를 아는 페이지의 `requirePageSession()`이 한다). 조회 함수가 접근을 확인하고, 없는 지점이거나 접근할 수 없으면(`NOT_FOUND`) `notFound()`다. 그 밖의 오류는 그대로 던져 오류 화면으로 간다.
  - 이 레이아웃은 `/branches/[branchId]`(층을 고르기 전의 주소)도 감싼다. 주소에 `floorId`가 없으면 지점 줄과 선택 표시 없는 층 탭만 그리고 날짜 줄은 그리지 않는다.
  - 레이아웃이 내려준 "오늘"과 "지금"은 화면을 연 때의 값이다. 액션 뒤의 다시 읽기로 새로 고쳐지고, 그 밖에는 자정을 넘겨도 바뀌지 않는다. 판정은 언제나 서버가 다시 한다.
- 클라이언트 컴포넌트와 스켈레톤은 렌더링 중에 `new Date()`나 `Date.now()`를 부르지 않는다. "오늘"과 "지금"은 서버가 읽어 props로 내려준다.
- 페이지 안의 `<Suspense>`에는 바뀌는 값을 `key`로 준다 (공간 목록은 층과 날짜, 공간 상세는 공간과 날짜). 클라이언트의 낙관적 스켈레톤과 서버의 fallback은 같은 스켈레톤 컴포넌트를 쓴다. 둘 사이가 이어져 보여야 한다.
- `key`를 정하려면 페이지가 `searchParams`를 읽어야 하므로 그 바깥에 `<Suspense>`가 하나 더 필요하다. 낙관적 값을 나누는 컨텍스트를 감싸는 `<Suspense>`도 같다. 이 바깥쪽 fallback은 둘 다 층 화면 전체의 스켈레톤이다 (`ui-loading-first.png`. 오른쪽은 "공간을 골라 주세요" 상자 자리).
- 공간만 바꾸는 이동에서 React는 이미 보이는 공간 목록이 새로 그려질 때까지 이동 전체를 붙잡는다 (목록의 `key`가 그대로이기 때문이다). 그래서 주소가 바뀌고 상세가 나오는 때는 목록과 상세 조회 중 늦은 쪽이다. 그동안 낙관적 선택 표시와 상세 스켈레톤이 보이므로 정상 동작이다. `useOptimistic`이 잘못된 것으로 보고 고치려 하지 않는다.

### 액션

- 제출 중인 버튼은 비활성이고, 글자가 "…하고 있어요"로 바뀌고, 작은 회전 표시가 붙는다. 버튼의 너비가 바뀌지 않는다.
- 성공하면 토스트를 띄우고 그 영역의 서버 데이터를 다시 읽는다. 다시 읽는 동안 이전 내용을 그대로 두고, 영역 전체를 스켈레톤으로 바꾸지 않는다.
- 목록에서 한 줄을 없애는 동작(취소, 거절)은 그 줄만 흐리게 하고 버튼을 비활성으로 둔다.

### 오류와 빈 화면

- `app/(app)/error.tsx`, `app/admin/error.tsx`, `app/error.tsx`를 둔다: "문제가 생겼어요. 잠시 뒤 다시 시도해 주세요"와 "다시 시도" 버튼. 오류의 내용을 화면에 출력하지 않는다. `app/error.tsx`는 그룹의 레이아웃에서 난 오류를 받는다.
- "다시 시도"는 서버 데이터를 다시 읽어야 한다. 설치된 Next.js 문서의 `error.md`가 안내하는 다시 시도 방법을 쓴다. 오류 경계만 되돌리고 서버 컴포넌트를 다시 읽지 않는 방식은 같은 오류 화면이 다시 나오므로 쓰지 않는다.
- `app/(app)/not-found.tsx`, `app/admin/not-found.tsx`, `app/not-found.tsx`를 둔다: "찾을 수 없는 화면이에요"와 "홈으로"(운영자 화면에서는 "운영자 홈으로"). 그룹 안의 것은 머리글이나 왼쪽 메뉴가 남는다.
- 빈 목록은 한 줄 설명과 다음에 할 일 하나를 같이 보여준다 (예: "예약이 아직 없어요"와 "공간 예약하기").

## 화면

### 홈 (`/`)

`ui-home.png`. 들어오자마자 쓸 정보를 보여준다. 카드마다 따로 읽고 따로 스켈레톤을 보여준다.

- 머리: "안녕하세요, {이름}님". 설명 줄은 "{날짜} · {지점}은 오늘 {끝}까지 열어요". 지금이 운영 시간 밖이면 "{날짜} · {지점}은 지금 운영 시간이 아니에요", 홈이 쓰는 지점이 없으면 날짜만. 오른쪽에 "공간 예약하기"(`/booking`).
- 왼쪽 열
  - 다가오는 내 예약: 내가 예약한 확정 예약 중 끝나지 않은 것을 시작순으로 3건까지. 한 줄에 날짜("오늘"은 생략하고 진행 중이면 "지금 이용 중" 배지, 내일은 "내일 · 10월 8일 목"), 시간, 공간 이름, "지점 · 층 · 개인 또는 팀 이름 · 제목". 줄을 누르면 그 날짜의 그 공간으로 간다. 없으면 "예약이 아직 없어요"와 "공간 예약하기". 오른쪽 위에 "내 예약 모두 보기". 이 카드는 지점과 상관없이 내 예약 전부에서 고른다.
  - 지금 비어 있는 공간: 홈이 쓰는 지점(아래)에서, 내가 접근할 수 있고 예약할 수 있는 공간 중 지금 비어 있는 것을 4곳까지. 한 줄에 이름, "층 · 정원 · 편의 시설", 오늘의 가용 시간 띠, "{시각}까지 비어 있음". 줄을 누르면 오늘의 그 공간으로 간다. 아래에 "예약할 수 있는 공간 N곳 중 M곳이 비어 있어요"와 "{지점} 전체 보기". 오른쪽 위에 "지점 바꾸기"(`/branches`).
- 오른쪽 열
  - 오늘 예약 한도: 그 지점에서 개인으로 예약할 때 오늘 남은 시간과 하루 한도. 내 역할에 개인 예약 권한(`booking.own`)이 없거나, 한도가 없거나(null, 운영자), 홈이 쓰는 지점이 없으면 카드를 보여주지 않는다.
  - 내 팀: 팀 이름과 내 역할. 받은 초대가 있으면 "받은 초대 N개"를 수락 대기 색으로 맨 위에 둔다. 팀이 없으면 "아직 속한 팀이 없어요…"와 "팀 만들기 또는 가입"(`/teams/start`). 오른쪽 위에 "팀 관리"(`/teams`).
  - 운영자에게만: "운영자 화면" 링크 한 줄.

홈이 쓰는 지점은 `getBookingEntry()`와 같다: 기본 지점, 없으면 이름순으로 본 내 팀의 주 이용 지점. 둘 다 없으면 "지금 비어 있는 공간" 자리에 "이용할 지점을 골라 주세요"와 "지점 고르기"(`/branches`)를 보여준다. 지점은 있는데 내가 접근할 수 있는 층이 없으면 "이 지점에는 이용할 수 있는 층이 아직 없어요"와 "지점 바꾸기"(`/branches`)를 보여준다.

"지금 비어 있다"는 지금이 그 지점의 운영 시간 안이고, 그 공간에 지금 진행 중인 확정 예약과 점검이 없다는 뜻이다. "{시각}까지"는 다음 예약이나 점검의 시작, 없으면 그날의 운영 종료다. 순서는 비어 있는 시간이 긴 것 먼저, 같으면 층 순서, 이름순이다. 운영 시간 밖이면 목록 대신 "지금은 운영 시간이 아니에요. {다음 운영일} {시작}에 열어요"와 "다른 날짜 보기"(`/booking`)를 보여준다. {다음 운영일}은 오늘이면 "오늘", 내일이면 "내일", 그 뒤면 요일("토요일")이다. 접근할 수 없는 공간은 수에도 목록에도 들어가지 않는다.

### 공간 예약으로 들어가기 (`/booking`)

화면이 없는 주소다. 홈이 쓰는 지점의, 내가 접근할 수 있는 첫 층으로 보낸다. 지점이 없으면 `/branches`로, 그 지점에 접근할 수 있는 층이 없으면 `/branches/[branchId]`로 보낸다. 한 번의 이동으로 층 화면에 닿게 한다 (`/branches/[branchId]`를 거치지 않는다). 갈 곳을 읽는 동안의 fallback은 층 화면의 스켈레톤이다 (보내기 전에 응답이 시작되므로 잠깐 보인다).

### 지점 목록 (`/branches`)

`ui-branches.png`.

- 카드 전체가 그 지점으로 가는 링크다. 버튼을 따로 눌러야 넘어가는 구조를 없앤다. 카드를 눌러도 기본 지점은 바뀌지 않는다.
- 카드: 지점 이름, "기본 지점" 배지(내 기본 지점에만), 주소, 상태 줄, "층 N개 · 지금 빈 공간 M곳".
- 상태 줄: 운영 중이면 초록 점과 "영업 중 · {끝}까지", 오늘 열지만 아직 전이면 "{시작}에 열어요", 오늘 끝났으면 "오늘 영업이 끝났어요", 쉬는 날이면 "쉬는 날이에요". 점의 색만으로 구분하지 않는다.
- "층 N개"는 내가 접근할 수 있는 층의 수다. "지금 빈 공간"은 홈과 같은 뜻으로 센다: 내가 접근할 수 있고 예약할 수 있는 공간(회의실, 폰부스 등 종류를 가리지 않는다) 중 지금 비어 있는 것. 운영 중이 아니면 보여주지 않는다. 접근할 수 있는 층이 없으면 "이용할 수 있는 층이 아직 없어요"를 대신 보여준다.
- 카드 아래에 "기본 지점으로 설정" 버튼이 있다 (기본 지점이 아닌 카드에만). 누르면 `setDefaultBranch`를 부르고 이동하지 않는다. 기본 지점 카드 아래에는 "홈과 공간 예약이 이 지점으로 먼저 열려요"를 보여준다.
- 기본 지점이 맨 앞, 나머지는 이름순.

기본 지점을 저장하는 때가 바뀐다 (`docs/spec/booking.md`에도 반영돼 있다): 지점을 고를 때가 아니라 "기본 지점으로 설정"을 누를 때, 그리고 기본 지점이 없는 사용자가 예약에 성공했을 때 그 지점으로.

### 층 화면 (`/branches/[branchId]/floors/[floorId]`)

`ui-floor.png`.

- 지점 줄: 지점 이름 버튼(누르면 `dropdown-menu`로 지점 목록과 "모든 지점 보기"), 그 옆에 그 날짜의 운영 상태("영업 중 · 08:00–22:00", 다른 날짜면 "08:00–22:00", 쉬는 날이면 "쉬는 날").
- 층 탭: 내가 접근할 수 있는 층. 날짜는 유지하고 공간 선택은 뺀다.
- 날짜 줄: 7일을 한 줄로 보여준다. 첫 칸은 "오늘 + 7×k일"이고 고른 날짜가 그 7일 안에 들게 k를 정한다. 칸에는 요일과 날짜(오늘은 "오늘")를 쓴다. 날짜를 바꾸면 공간 선택은 유지한다.
  - 쉬는 날은 흐리게 하되 누를 수 있고, 칸에 "쉬는 날"이라는 글자가 있다 (작은 글자로 보이거나 화면에 보이지 않는 글자). 흐림만으로 알리지 않는다.
  - 범위는 오늘부터 60일 뒤까지다. 마지막 줄에서 60일을 넘는 칸은 비활성이다.
  - 왼쪽 화살표는 "고른 날짜 − 7일", 오른쪽 화살표는 "고른 날짜 + 7일"로 가는 링크다. 범위를 넘으면 오늘 또는 60일 뒤로 맞춘다. 첫 줄에서는 왼쪽이, 60일 뒤가 들어 있는 줄에서는 오른쪽이 비활성이다.
- 공간 목록: 종류별 묶음. 묶음 안에서는 이름순이고 전용 공간은 맨 뒤다.
  - 묶음 제목 옆에 "N곳 · 지금 M곳 비어 있음". N은 그 묶음에 보이는 줄의 수(전용 공간 줄 포함)이고, M은 내가 접근할 수 있고 예약할 수 있는 공간 중 지금 비어 있는 수다. 전용 공간은 M에 들어가지 않는다. M이 0이거나, 오늘이 아니거나, 운영 중이 아니면 "N곳"만 쓴다.
- 공간 줄: 이름, "정원 · 편의 시설", 상태 배지(오늘만), 요약, 가용 시간 띠. 줄 전체가 링크다.
  - 요약(오늘): 비어 있으면 "{시각}까지", 사용 중이면 "{시각}부터 비어 있음"(오늘 더 빈 시간이 없으면 "오늘은 빈 시간이 없어요"), 점검 중이면 "{끝}까지". 내 예약이 진행 중이면 "{끝}까지".
  - 끝이 오늘이 아닐 수 있는 것은 점검뿐이다. 끝이 내일이면 "내일 12:00까지", 그 뒤면 "10월 9일 12:00까지"로 쓴다.
  - 요약(다른 날짜): "예약 N건".
  - 예약할 수 없는 공간은 띠 없이 "예약 없이 이용해요" 또는 "좌석 N석 · 좌석 예약은 준비 중이에요".
- 전용 공간 줄: 자물쇠와 "전용 공간 · 다른 팀이 쓰는 공간이에요". 누를 수 없다. 이름, 정원, 띠가 없다. 자물쇠 아이콘은 `aria-hidden`이고 글자가 뜻을 전한다.
- 공간을 고르지 않았을 때 오른쪽: 점선 테두리 상자에 "공간을 골라 주세요"와 한 줄 설명.

가용 시간 띠

- 그날의 운영 시작부터 끝까지를 한 줄로 그린다. 바탕은 "비어 있음" 색, 남의 예약은 회색, 내 예약(내가 했거나 내 팀 이름으로 된 것)은 강조 색, 점검은 빗금. 오늘이면 지난 부분을 흐리게 덮고 지금 시각에 세로선을 둔다.
- 띠 아래에 시각 눈금을 4시간 간격으로 쓴다 (홈의 작은 띠에는 쓰지 않는다). 눈금은 `aria-hidden`이다.
- 띠는 장식이 아니다. `role="img"`와 이름을 준다. 이름에는 구간의 종류가 들어간다: "예약 10:00–11:30, 내 예약 13:00–14:00, 점검 15:00–16:00". 구간이 없으면 "예약된 시간이 없어요". 색만으로 종류를 알리지 않는다.
- 띠에 쓰는 데이터는 구간의 시작, 끝, 종류(남, 내 것, 점검)뿐이다. 예약자 이름과 제목은 목록 조회에 싣지 않는다. 접근할 수 없는 공간의 구간은 싣지 않는다.

공간 상세

- 세 부분이다: 위(이름, "N층 · 최대 N인", 상태와 편의 시설 배지, 닫기), 가운데(하루 일정), 아래(예약 양식). 1024px 이상에서는 패널이 화면에 붙어 따라오고(`position: sticky`), 패널의 높이가 화면보다 크면 가운데만 스크롤된다. 예약 양식은 언제나 보인다.
- 하루 일정은 격자다: 왼쪽에 정시 눈금, 30분이 한 칸(28px). 예약과 점검은 여러 칸에 걸친 블록 하나로 그린다. 블록에는 시간과 예약자(보이는 사람에게는 제목), 취소할 수 있으면 "취소"가 있다. 지금처럼 칸마다 "예약 중"을 되풀이하지 않는다.
- 빈 칸은 버튼이다. 이름은 "15:00, 비어 있음"처럼 읽힌다. 지난 칸, 예약된 칸, 점검 칸은 버튼이 아니다. 칸의 높이는 패널에서 28px, 시트에서 44px이다.
  - 빈 칸들은 `role="group"`과 이름("{날짜} 빈 시간")을 가진 묶음이다. Tab으로는 이 묶음에 한 번만 멈추고, 위아래 화살표로 빈 칸 사이를 옮긴다 (roving tabindex). Enter와 Space로 고른다.
  - 블록 안의 "취소"와 "지난 시간 보기"는 이 묶음에 들지 않는다. 평소처럼 Tab으로 하나씩 멈춘다.
  - 고른 구간에 들어 있는 칸은 `aria-pressed="true"`다.
- 오늘이면 지금이 속한 칸부터 보여준다. 그 앞은 접어 두고 "지난 시간 보기 · {시작}–{끝} (예약 N건)" 버튼으로 편다 (`aria-expanded`). 다른 날짜는 전부 보여준다. 지금 시각에는 가로선을 둔다.
- 고른 구간은 점선 테두리의 "새 예약 {시작}–{끝}" 블록으로 보인다. 예약 양식의 요약 줄은 `aria-live="polite"`라서 구간이 바뀌면 읽힌다.
- 칸을 누르는 규칙: 시작이 없으면 그 칸이 시작이 되고 끝은 1시간 뒤(다음 예약, 점검, 운영 종료에 걸리면 그 전)다. 시작이 있는 상태에서 그 뒤의 빈 칸을 누르면, 시작부터 그 칸까지가 모두 비어 있을 때 끝을 그 칸의 끝으로 바꾼다. 그렇지 않으면 그 칸이 새 시작이 된다. 이 규칙은 순수 함수로 두고 테스트한다.
- 예약 양식: 고른 구간의 요약("10월 7일 수 · 15:30–16:30"과 길이), 시작·끝 선택 상자, "개인으로 / 팀으로"(지금 규칙 그대로), 한도 한 줄, "제목 추가"를 누르면 나오는 제목 입력, "예약하기". 구간을 고르기 전에는 요약 자리에 "시간을 골라 주세요"를 보여주고 버튼은 비활성이다.

### 내 예약 (`/bookings`)

`ui-bookings.png`.

- 탭 두 개: "다가오는 예약 N", "지난 예약". 탭은 주소의 `?tab=past`로 가는 링크다 (`nav` 안의 `<a>`, 지금 것에 `aria-current="page"`).
- 날짜별로 묶는다. 묶음 제목은 "오늘 · 10월 7일 수요일", "내일 · …", 그 밖은 날짜만.
- 한 줄: 시간, 공간 이름과 "지점 · 층 · 개인 또는 팀 이름 · 제목", 상태, 동작. 상태는 진행 중이면 "지금 이용 중", 시작까지 60분 미만이면 "N분 뒤"(올림, 최소 1), 60분 이상 24시간 미만이면 "N시간 뒤"(내림), 그 밖은 없음. 지난 예약은 "이용 종료" 또는 "취소됨".
- 다가오는 예약의 공간 이름은 그 날짜의 그 공간으로 가는 링크다. "취소"는 지금처럼 확인을 거친다.
- 오른쪽 위에 "공간 예약하기".

### 팀 (`/teams`)

새 화면이다. `ui-teams.png`. 팀에 관한 것을 한곳에 모은다.

- 받은 초대: 있을 때만 맨 위에 보인다. 팀 이름, 초대한 사람, 만료일, 메시지, "거절"과 "수락". 수락하면 그 팀 화면으로 간다.
- 내 팀: 팀 이름, "팀원 N명 · 주 이용 지점 {지점}", 내 역할. 줄을 누르면 팀 화면으로 간다. 없으면 "아직 속한 팀이 없어요"와 "팀 만들기 또는 가입".
- 보낸 가입 요청: 대기 중인 요청과, 최근 30일 안에 거절된 요청. 대기 중이면 "승인 대기"와 "요청 취소", 거절됐으면 "거절됨"과 "다시 요청". 승인된 요청은 내 팀에 나오므로 여기 없다. 하나도 없으면 이 구역을 보여주지 않는다.
  - "최근 30일"은 `decided_at ≥ 지금 − 30일`이다. 지금은 조회에 주입하는 값이다.
  - 거절된 요청은 그 팀에 더 새로운 내 요청이 있거나 내가 이미 그 팀의 팀원이면 보여주지 않는다. 팀마다 가장 최근 것 하나만 보여준다.
  - "다시 요청"은 `/teams/start?mode=join&q={팀 이름}`으로 가는 링크다. 요청을 바로 보내지 않는다.
- 오른쪽 위에 "팀 만들기 또는 가입"(`/teams/start`).

### 팀 회원으로 전환 (`/teams/start`)

`ui-teams-start.png`, `ui-teams-create.png`, `ui-teams-join.png`. 한 페이지에 세 구역을 펼쳐 두던 것을 "먼저 고르고, 고른 것만"으로 바꾼다. 단계는 주소의 `?mode=`다. 뒤로 가기가 단계를 되돌린다.

- 고르기 (`mode` 없음): 카드 두 장. "새 팀 만들기 — 우리 팀이 아직 Floor에 없을 때", "기존 팀에 가입 — 우리 팀이 이미 Floor를 쓰고 있을 때". 카드마다 무슨 일이 일어나는지 세 줄로 적는다. 받은 초대가 있으면 카드 위에 "{팀 이름}에서 초대가 와 있어요. 수락하면 바로 팀원이 돼요"와 "초대 보기"(`/teams`)를 띄운다. 초대가 여럿이면 "받은 초대가 N개 있어요".
- 새 팀 만들기 (`mode=create`): 양식만 있는 화면. "팀 정보"(이름, 주 이용 지점, 인원 규모)와 "담당자"(연락처, 직함) 두 묶음. 입력마다 규칙을 도움말로 적는다. 아래에 "취소"와 "팀 만들기". 위에 "다시 고르기". 입력 규칙과 저장은 지금 그대로다.
- 기존 팀에 가입 (`mode=join`): 검색 상자와 결과. 결과의 "가입 요청"을 누르면 그 줄이 펼쳐져 메시지 입력과 "요청 보내기"가 나온다. 이미 팀원이면 "이미 팀원이에요", 받은 초대가 있으면 "받은 초대가 있어요", 대기 중인 요청이 있으면 "요청을 보냈어요"를 버튼 대신 보여준다. 요청을 보내면 토스트는 지금 문구 그대로("가입 요청을 보냈어요. 팀 관리자가 승인하면 팀원이 돼요", `docs/spec/auth.md`)이고, 그 줄이 "요청을 보냈어요"로 바뀌며 `/teams`로 가는 링크("보낸 요청 보기")가 나온다. 검색어는 지금처럼 `?q=`다.
- 받은 초대의 수락·거절과 보낸 요청의 목록·취소는 `/teams`로 옮긴다. 이 화면에는 두지 않는다.

## 운영자 화면

구성은 `docs/spec/space-admin.md` 그대로다. 다듬을 것만 적는다.

- 선택 상자(shadcn `select`)는 서버가 그린 HTML에서도 고른 값이 글자로 보여야 한다. 지금은 스크립트가 실행되기 전까지 비어 보인다 (지점 화면의 운영 시간 14개, 공간 양식의 종류). `SelectValue`에 고른 항목의 글자를 직접 넘긴다. 처음부터 값이 있는 선택 상자 전부에 해당한다.
- 경로 표시: 내용 위에 "지점 › 강남점 › 7F". 각 단계가 링크다.
- 운영자 홈: 지점마다 카드 하나. 이름, 주소, 오늘의 운영 상태, "층 N개 · 공간 N곳". 카드 전체가 링크다.
- 지점 화면: "지점 정보", "운영 시간", "층" 세 구역. 운영 시간은 요일마다 한 줄(요일, "쉬는 날" 스위치, 시작, 끝)인 표로 줄인다. "월요일 시간을 평일 전체에 적용" 버튼을 둔다. 층은 표(층 번호, 이름, 이용 대상, 공간 수)이고 줄 전체를 눌러 층 화면으로 간다. 표의 줄을 누를 수 있게 할 때는 첫 칸의 글자를 링크로 하고 그 링크의 `::after`를 줄 전체로 늘린다. `<tr>`에 클릭 처리를 달거나 `<tr>`을 `<a>`로 감싸지 않는다.
- 층 화면: 공간 표를 종류별로 묶고 이름순으로 둔다. 예약 가능은 "가능/불가" 글자 대신 체크 표시와 화면에 보이지 않는 글자, 이용 대상은 배지. 줄의 동작은 `dropdown-menu` 하나("고치기", "이용 대상", "보관" 또는 "되살리기")로 모은다. "고치기"와 "이용 대상"은 지금의 대화상자를 연다 ("이용 대상"은 그 대화상자의 이용 대상 구역으로 바로 간다). 권한이 없어도 항목은 눌리고, 대화상자 안에서 권한이 없는 구역이 읽기 전용으로 보인다 (`docs/spec/space-admin.md` 그대로). "보관"과 "되살리기"만 권한이 없으면 비활성이고 이유를 적는다. 보관된 공간은 흐리게 하고 "보관됨" 배지를 붙인다 (흐림만으로 알리지 않는다).
- 왼쪽 메뉴의 "로그아웃"은 메뉴 맨 아래에 고정한다.
- 스켈레톤과 "바뀌는 부분만 바꾼다"는 멤버 화면과 같은 규칙이다.

## 로그인과 가입 화면

구성과 규칙은 `docs/spec/auth.md` 그대로다.

- 1024px 이상에서 화면을 둘로 나눈다. 왼쪽은 서비스 소개(이름, 한 줄 설명 "공유오피스의 빈 공간을 찾아 바로 예약해요", 할 수 있는 일 세 줄), 오른쪽은 지금의 카드. 그보다 좁으면 카드만. 운영자 로그인(`/admin/login`)에는 소개 칸을 두지 않는다. 지금처럼 카드 하나다. `(auth)` 레이아웃은 운영자 로그인도 감싸고 서버에서 주소를 알 수 없으므로, 두 칸 틀은 레이아웃이 아니라 멤버용 인증 페이지들이 쓰는 공용 컴포넌트로 만든다.
- 소셜 버튼에 제공자의 표시(글자 "G", GitHub는 lucide 아이콘이 있으면 그것)를 붙인다. 로고 이미지를 새로 그리거나 내려받지 않는다.
- 비밀번호 입력에 "보기/숨기기" 버튼을 둔다. 버튼의 이름이 상태에 따라 "비밀번호 보기", "비밀번호 숨기기"로 바뀐다 (`aria-pressed`를 같이 쓰지 않는다). 가입 화면에는 "8자 이상"을 도움말로 적는다.
- fallback("화면을 준비하고 있어요.")을 카드 틀의 스켈레톤으로 바꾼다.
- 메일 안내 화면(`/verify-email`)에 지금 무엇을 해야 하는지를 번호 세 줄로 적는다: 메일함 열기, 링크 누르기, 돌아와서 로그인하기. 개발 환경에서는 "개발 중에는 메일이 실제로 가지 않아요. 서버 로그의 링크를 열어 주세요"를 한 줄 더 보여준다 (`NODE_ENV`가 `production`이 아닐 때만).

## 구현에서 확정한 경계

- 홈이 쓰는 지점이 없으면 날짜는 `Asia/Seoul` 기준이다. 팀의 주 이용 지점이 대체값이면 머리말과 카드 모두 그 지점을 쓴다.
- 모든 요일이 휴무이면 다음 운영 시각은 null이다. "운영 예정 시간이 없어요"와 지점 변경 링크를 보여준다. 운영 시간 저장 규칙은 바꾸지 않는다.
- 시트는 주소의 `space` 자체가 아니라 서버가 확인한 실제 공간 id 또는 진행 중인 낙관적 선택으로만 연다. 잘못되거나 접근 불가한 공간은 선택 없음이다.
- 가용 시간 띠는 점검을 우선 표시한다. 상세에서 점검과 기존 예약이 겹치면 나란히 배치해 예약 정보와 취소 버튼을 가리지 않는다.
- 운영자 홈의 공간 수는 보관되지 않은 비좌석 공간만 센다.

## 하지 않는 것

- 평면도(Canvas), 실시간 갱신, 낙관적 예약 반영 (PFQV-2, PFQV-19, PFQV-24)
- 다크 모드의 색 정하기
- 세션을 쿠키에 캐시해 DB 확인을 건너뛰기. 비밀번호를 재설정하면 세션이 바로 끊겨야 한다는 규칙과 부딪힌다
- 새 기능: 예약 시간 변경, 좌석 예약, 팀원 역할 변경, 알림
- 화면 전환 애니메이션 (View Transitions)
